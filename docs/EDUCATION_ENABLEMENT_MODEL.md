# Education Enablement Model

## Intent

UAF should enable education as part of its responsible community economy.

Education is not just marketing. It is how the community learns the protocol,
how builders become capable, how enterprises adopt safely, and how the ecosystem
creates fair economic progression.

```text
learn -> practice -> build -> verify -> certify -> earn -> teach
```

## Principle

The basic learning path should be open. Advanced enablement, certification,
enterprise workshops, and partner training can be monetized.

```text
Open education creates adoption.
Paid enablement creates sustainability.
Certification creates trust.
```

## Education layers

| Layer | Audience | Open/community | Paid/commercial |
| --- | --- | --- | --- |
| Fundamentals | New users | docs, glossary, quickstarts | guided cohort |
| Practitioner | Developers/builders | examples, labs, sample sessions | hands-on workshop |
| Operator | Platform/security teams | deployment guide, OPA examples | enterprise ops training |
| Auditor | GRC, risk, compliance | evidence model docs | audit evidence workshop |
| Partner | Consultants/MSPs/SIs | partner overview | certified partner program |
| Research | Academics/researchers | whitepapers, benchmarks | research sponsorship, seminars |
| Executive | Buyers/leaders | public briefings | private executive enablement |

## Open education artifacts

The community edition SHOULD include:

```text
docs/getting-started.md
docs/glossary.md
docs/tutorials/first-session.md
docs/tutorials/opa-policy.md
docs/tutorials/evidence-report.md
examples/tasks/basic-task.json
examples/sessions/basic.jsonl
reports/templates/session-summary.report.json
```

These artifacts should teach:

- what UAF is,
- what UAP entries are,
- how a workspace log works,
- how replay works,
- how OPA policy gates execution,
- how evidence entries support review,
- how reports are generated.

```text
UAF Evidence and Audit Course

UAF Enterprise Adoption Workshop
UAF Partner Certification
UAF Executive Briefing
UAF Train-the-Trainer Program
```

## Certification ladder

Certification should measure practical capability, not memorization.

```text
UAF Foundations
  -> UAF Practitioner
  -> UAF Operator
  -> UAF Policy Author
  -> UAF Evidence Auditor
  -> UAF Certified Partner
  -> UAF Certified Trainer
```

Each certification should require a signed artifact submission:

```text
workspace log
policy file
replay report
evidence bundle
report output
reflection/notes
```

## Learning-by-artifact model

Students should produce real artifacts while learning.

Example learning path:

1. write a natural-language task,
2. convert it into a UAP task entry,
3. run the session,
4. inspect the workspace JSONL,
5. add a constraint,
6. evaluate OPA policy,
7. emit evidence,
8. replay the session,
9. generate a report,
10. sign and submit the evidence bundle.

This makes education directly useful for the community and enterprise buyers.

## Responsible education rules

UAF education must be honest about limits.

Allowed claims:

```text
evidence-emitting
policy-gated
replayable
control-mapped
SOC 2 aligned
GDPR aligned
cloud-native
Kubernetes-native
```

Avoid unsupported claims:

```text
automatically compliant
guaranteed audit pass
certified secure by default
replaces legal review
replaces compliance officers
```

## Community economic progression

Education should create income paths:

```text
Learner
  -> Contributor
  -> Builder
  -> Verified Builder
  -> Certified Practitioner
  -> Marketplace Seller
  -> Certified Partner
  -> Trainer / Advisor
```

The company should support this progression with:

- free entry-level materials,
- public examples,
- clear certification criteria,
- fair artifact review,
- attribution,
- partner pathways,
- revenue-sharing terms where marketplace artifacts are sold.

## Enterprise enablement

Enterprise education should focus on adoption and risk reduction.

Enterprise workshops:

```text
UAF for Platform Teams
UAF for Security Teams
UAF for GRC Teams
UAF for AI Governance Teams
UAF for Kubernetes Operators
UAF Evidence Bundle Workshop
UAF OPA Policy Workshop
```

Enterprise outcomes:

- deploy the runtime,
- run a controlled session,
- verify evidence,
- generate an audit report,
- map controls,
- define internal ownership,
- prepare production rollout plan.

## Research education

Research-facing education should produce publishable artifacts:

```text
technical reports
benchmarks
replay datasets
case studies
reference architectures
conference decks
standards proposals
```

The research layer should connect UAF to broader topics:

- agent governance,
- evidence-emitting AI systems,
- policy-gated execution,
- reproducible agent workflows,
- auditability of natural-language work,
- cloud-native AI operations.

## Monetization without exploitation

Education can be monetized responsibly through:

```text
paid cohorts
certification exams
enterprise workshops
partner training
custom enablement
implementation bootcamps
training licenses
train-the-trainer programs
```

But the basic ability to understand and run UAF should remain accessible.

## Education artifact packaging

Each educational artifact should be:

```text
versioned
licensed
attributed
signed when official
mapped to skill outcomes
mapped to product artifacts
connected to a learning path
```

## Done condition

Education enablement is ready when UAF has:

1. a beginner quickstart,
2. a first-session tutorial,
3. an OPA policy tutorial,
4. an evidence report tutorial,
5. a certification ladder,
6. a partner enablement path,
7. a paid enterprise workshop outline.

## Final rule

Education is part of the product.

A responsible corporation does not only sell software. It creates the knowledge,
skill, trust, and economic pathways that let people use the software safely and
benefit from the ecosystem.
